# 데이터 시스템 트레이드오프 예제: 운영 DB와 분석 DB를 나누는 이유 (파이썬 표준 라이브러리만)

온라인 서점의 주문 DB(운영, OLTP)에 주문 20만 건을 넣고, 매출 보고서(분석, OLAP)를 돌린다.

| 파일 | 역할 |
|---|---|
| `shop.py` | 주문 DB 만들기, 웨어하우스로 복사(가장 단순한 ETL), 주문 한 건(`checkout`), 매출 보고서(`report`) |
| `demo.py` | 보고서를 ① 안 돌릴 때 ② 같은 DB에서 돌릴 때 ③ 웨어하우스에서 돌릴 때, 주문 한 건이 걸린 시간 |
| `solutions/` | 연습 문제 풀이 |

```bash
python3 demo.py
python3 -m unittest
```

SQLite는 읽는 동안 파일에 공유 잠금을 걸어 쓰기를 기다리게 한다. 그래서 같은 DB에서 보고서를 돌리면 주문이 줄을 선다.
PostgreSQL·MySQL 같은 서버 DB는 읽기가 쓰기를 막지 않는 대신(MVCC), 같은 CPU·디스크·메모리를 나눠 쓰느라 느려진다. 원인은 달라도 결론은 같다.
시간 숫자는 컴퓨터마다 다르다. 200,000건·1위 책·건수 같은 숫자는 seed가 고정이라 같다.

## 연습 문제

웨어하우스는 복사한 순간의 사진이라 새 주문이 빠진다. `shop.py`에 `sync(orders, warehouse)`를 만들어,
웨어하우스에 없는 주문(id가 가장 큰 id보다 큰 것)만 옮겨 보세요. 통째로 다시 복사하지 않습니다.
풀이: `python3 solutions/sync.py`
