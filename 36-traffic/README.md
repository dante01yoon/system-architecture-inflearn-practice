# traffic — 트래픽이 몰릴 때 제일 먼저 할 일

신간 출간일의 온라인 서점 모형(`sim.py`): 평소 초당 100건이 30초 동안 초당 1,000건(10배)으로 몰린다. 요청은 1초 단위로 앱 서버 → (캐시) → DB를 지나고,
단계마다 1초에 할 수 있는 일(코어 × 1,000ms)을 넘친 만큼 줄이 쌓인다. 무작위가 없어 언제 돌려도 같은 결과가 나온다. 표준 라이브러리만 쓴다.

    python3 demo.py 1   # 먼저 재기: 읽기·쓰기 비율, 단계별 사용률, 줄이 쌓이는 곳
    python3 demo.py 2   # 하나씩 고치기: 앱 서버 늘리기 → 읽기 캐시 → 연결 풀 맞추기
    python3 -m unittest
    python3 solutions/hit_rate.py   # 연습 문제 풀이

숫자는 모두 설명을 위해 정한 가정이다(앱 CPU 2ms, DB 읽기 5ms·쓰기 10ms, 앱 서버 2코어, DB 4코어, DB 연결 한도 100).
단순화: 줄은 「남은 일의 양 ÷ 처리 속도」로만 기다림을 셈한다. 연결 한도를 넘긴 몫의 요청은 DB에 닿기 전에 바로 오류로 센다.
