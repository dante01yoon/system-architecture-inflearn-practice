# ddia-storage — 저장소 엔진 장난감: LSM-tree 대 B-tree, 줄 저장 대 칸 저장

파이썬 표준 라이브러리만 쓴다. 숫자는 이 장난감 코드에서 잰 값이다(실제 엔진은 캐시·블록 인덱스·블룸 필터·압축이 있어 다르다).

| 파일 | 역할 |
|---|---|
| `lsm.py` | WAL 덧붙이기 → 메모리 표(memtable) → 가득 차면 정렬된 세그먼트 파일(SSTable)로 → 4개가 되면 하나로 합치기(compaction) |
| `btree.py` | 4KB 페이지 목록을 정렬해 두고, 넣을 때마다 그 페이지를 통째로 다시 쓴다. 넘치면 반으로 쪼갠다 |
| `layout.py` | 같은 주문 표를 줄 단위(66바이트 줄) 파일과 칸 단위(칸마다 파일) 로 쓰고, 가격 합계를 읽은 바이트를 센다 |
| `demo.py` | 1 = 키 5만 개 쓰기·읽기(쓰기 증폭, 읽을 때 보는 파일·페이지 수), 2 = 가격 합계(줄 대 칸 대 사전 압축) |

    python3 demo.py 1
    python3 demo.py 2
    python3 -m unittest
    python3 solutions/bloom.py   # 연습 문제 풀이

가정: B-tree 페이지 4KB, 안쪽 페이지 하나가 자식 200개를 가리킨다고 셈(높이 계산). 넣을 때마다 바뀐 잎 페이지를 바로 디스크에 쓴다고 본다
(실제 DB는 페이지를 메모리에 모았다가 쓰므로 증폭이 이보다 작다). LSM의 합치기는 가장 단순한 방식(모두 하나로)이다.

## 연습 문제

LSM에서 없는 키를 찾으면 세그먼트 파일을 전부 열어 봐야 한다. 세그먼트마다 블룸 필터(있을 수도 있다 / 확실히 없다)를 붙여서,
없는 키 1만 번을 찾을 때 여는 파일 수가 얼마나 줄어드는지 재 보세요. 풀이: `python3 solutions/bloom.py`
