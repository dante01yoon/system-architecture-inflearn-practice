# 서점 위시리스트 · 연습지 (풀이 예시)

가정: 서점 회원 1,000만 명, 하루 활성 100만 명, 한 사람 위시리스트 평균 20권(모두 가정).

## 1. 기능 요구
- [x] 책을 위시리스트에 넣고 빼기
- [x] 내 위시리스트 보기(최근 넣은 순)
- [x] 위시리스트 책이 할인하면 알림 받기 — 이번엔 뺀다고 말함

## 2. 비기능 요구
- [x] 목록 보기 p99 200ms 안
- [x] 넣은 책은 잃지 않는다(내구성)
- [x] 다른 기기에서 몇 초 늦게 보여도 괜찮다(결과적 일관성)

## 3. 어림셈
- [x] 저장: 1,000만 명 × 20권 × 50바이트 ≈ 10GB — 한 대에 들어간다
- [x] 쓰기: 하루 100만 명 × 2번 ÷ 86,400초 ≈ 초당 23번 — 작다

## 4. 핵심 엔티티
- [x] User, Book, WishlistItem(user_id, book_id, added_at)

## 5. API
- [x] PUT /wishlist/{book_id} · DELETE /wishlist/{book_id} · GET /wishlist?cursor=

## 6. 큰 그림
- [x] 클라이언트 → API 서버(무상태 여러 대) → DB(user_id로 찾는 인덱스) · 책 정보는 캐시

## 7. 깊게 파기
- [x] 같은 책을 두 번 넣으면? → (user_id, book_id) 기본 키 + PUT이라 멱등
- [x] 인기 회원 목록이 수천 권이면? → cursor 페이지
